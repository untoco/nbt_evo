# Обновление ПО блоков BMW F21 N13B16

> Версия: 2026-11-17. Область: принадлежащий владельцу F21, VIN из [спецификации](../../vehicle/BMW_F21_N13B16_SPECS.md), включая ретрофит NBT Evo. Единый рабочий план исследования, подготовки и последующих проверок. Прошивка в этой задаче не выполнялась.

[Раздел ПО автомобиля](../README.md)

## Вывод

**Обновлять ПО программируемых блоков F21 технически можно.** BMW предусматривает программирование F-серии через ISTA [S1]. Но это не означает, что для каждого установленного блока существует более новая совместимая прошивка или что она принесёт пользу. Конкретные целевые версии и состав работ нашей машины — `unknown` до инвентаризации и расчёта плана.

Для нашего автомобиля разумный следующий шаг — получить полный состав ECU, FA/VO, SVT Actual, I-Step и ошибки, затем выбрать обновление под конкретную неисправность, бюллетень или функцию (`planned`). Автоматически обновлять всё ради даты не предлагается: у нас MHD, xHP, ретрофит HU/KOMBI и нестандартный аккумулятор. Это инженерная рекомендация по текущей конфигурации; она не отменяет применимые отзывные кампании и обязательные исправления.

## Что именно называется обновлением

| Операция | Что меняет | Отношение к задаче |
|---|---|---|
| Программирование ECU / flash | Исполняемое ПО, калибровки, при необходимости загрузчик | Основная тема; нужны совместимые образы и план программирования |
| Кодирование FDL / VO | Настройки и конфигурацию по комплектации | Отдельный [процесс настроек](../coding/plan.md); наличие BimmerCode не даёт flash ECU |
| MHD / xHP | Тюнинговые калибровки соответствующего силового блока | Не универсальный способ обновить FEM, DSC, HU и остальные ECU |
| Карты навигации | Картографические данные HU | Не обновление прошивки всего автомобиля |
| USB Software Update / UPD | Совместимость мультимедиа с телефонами/USB в поддерживаемых системах | BMW описывает отдельные такие пакеты [S7]; это не способ обновить двигатель, коробку и шасси |
| Remote Software Upgrade | OTA-программирование поддерживаемых автомобилей | Не рабочий путь для нашей конфигурации F21 с NBT Evo; бюллетень запуска RSU требует MGU [S8] |

Статус классификации — `reported` по документации производителей [S1, S3–S8]; применимость каждого пакета к конкретному ECU пока `unknown`. Ретрофит NBT Evo не превращает F21 в автомобиль с современной системой RSU.

## Пути обновления

### 1. ISTA: штатный сервисный процесс

`reported` BMW: для F/G-серии программирование встроено в ISTA; современная ISTA/P предназначена для более старых E/R-серий [S1]. Нужны клиент **и данные программирования**: установленный диагностический клиент сам по себе недостаточен [S1].

ISTA рассчитывает меры по состоянию автомобиля. План может затронуть несколько ECU: BMW прямо описывает автоматическое программирование/кодирование блоков, ПО которых требует обновления [S9]. Поэтому заказ «обновить только приборку» ещё не гарантирует такой состав фактического плана. До запуска нужно сохранить и разобрать все меры, включая кодирование, замены и последующие сервисные процедуры.

Для нас (`planned`): рассматривать сервис, который умеет работать с F-серией **с ретрофитами и тюнингом**, готов показать план до записи и объяснить судьбу HU, DME и EGS. Не предполагать, что стандартная процедура для заводской машины автоматически сохранит нашу конфигурацию.

### 2. E-Sys: инженерный путь с контролем состава

`reported` руководством E-Sys [S3]: инструмент работает с FA, SVT и TAL — рассчитанным списком действий программирования. Это кандидат для выборочного обновления с анализом зависимостей, а не универсальная кнопка «залить один файл».

Для подготовки (`planned`) нужны совместимая версия E-Sys и данные PSdZData **с образами ПО выбранных ECU**; сокращённого набора только для кодирования недостаточно. Проверять фактическое наличие нужных SWE, а не только название архива «Full». Сохранить FA, SVT Actual, рассчитанный SVT Target, TAL и результат проверки наличия программных компонентов. Серия данных нашего F21 — кандидат F020, что согласуется с ответом ZGW; точную цель подтверждать расчётом, а не названием кузова или чужой инструкцией.

Выбор одного блока допустим только после проверки зависимостей и совместимости. Не удалять из TAL связанные меры произвольно ради сохранения тюнинга. Если безопасно исключить DME/EGS/HU нельзя, пересмотреть объём работы и восстановление этих блоков. Не менять дату FA, аппаратные идентификаторы или VIN ради прохождения расчёта.

Готовность E-Sys для нашего конкретного набора HWEL/BTLD, лицензия/дистрибутив, наличие данных и проверенный сеанс — `unknown`. Пошаговую команду исполнения TAL до этих проверок не формируем.

### 3. Собственный клиент на macOS

`confirmed` по локальным материалам: наш Python-клиент умеет транспорт/идентификацию, готовой процедуры flash всех ECU в проекте нет. Программирование потребует значительно больше, чем UDS-чтение: управления сессиями, доступа, передачи образов, проверки зависимостей и целостности, тайм-аутов, перезапуска и обработки сбоев (`planned` как область разработки). Разработка возможна как отдельная задача, но сейчас это не готовый способ обновить автомобиль.

### Питание с нашей LTO

`planned`: подбирать программирующий источник с регулируемым стабильным выходом и достаточным **непрерывным** током под фактическую нагрузку автомобиля плюс потребление батареи. Число ампер на корпусе само по себе не обеспечивает пригодность. До сеанса получить требования производителя VISSO и источника, проверить режим с подключённой батареей и измерить напряжение под нагрузкой. Если диапазоны требований автомобиля и LTO не пересекаются — сначала решить питание с профильным специалистом.

Не назначаем универсальные «14.8 V / 100 A»: допустимая уставка этой батареи и необходимый ток не установлены. Не использовать импульсную десульфатацию/recondition; не выбирать AGM-режим по типовой BMW-инструкции без проверки LTO. Не заменять источник работающим двигателем и не отключать батарею произвольно. Подключение, зажигание и потребители — по инструкции конкретного автомобиля и инструмента, с записью напряжения во время сеанса.

`reported` MHD: общий FAQ не обещает чтение существующей тюнинговой карты в файл и говорит о повторной установке своих карт [S6]. Поэтому надпись Stage 1 и «backup кодировок» не считаются резервной копией DME. Для xHP актуальная документация [S4] допускает визит на обновление с установленным xHP; старое универсальное требование обязательно удалить его заранее не принимаем за действующее без проверки конкретного случая.

Сбой во время программирования (`planned`): сохранить питание, сообщение, этап и логи; не перебирать случайные прошивки и не выключать питание по общей интернет-инструкции. Действовать по recovery-процедуре выбранного клиента/ECU. Если загрузчик и диагностика доступны, повторная корректная запись может помочь; если нет — может понадобиться восстановление снятого блока либо замена. Возврат на предыдущую версию и сохранение всех функций заранее не гарантируются.

## Когда обновление оправдано

`planned`, критерии решения:

- Есть применимый по VIN/ECU бюллетень, кампания или диагностированная программная неисправность.
- Нужная функция действительно требует другой версии ПО и поддерживается установленным оборудованием.
- Для замены/ретрофита требуется согласование версий, которое подтверждено расчётом.
- Есть конкретный ожидаемый результат и способ проверить его до/после.

Пока ни один конкретный целевой пакет для нашей машины не выбран (`unknown`). Обновление не считать лечением перегрева, механического износа или заменой обслуживания АКП. BMW также отдельно предупреждала, что автоматическое обновление при каждом новом релизе часто не приносит ощутимой пользы [S8]; это общий принцип из бюллетеня RSU, а не специальная инструкция для нашего VIN.
